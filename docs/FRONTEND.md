```
    components/
    hooks/
    api/
    types/
    mocks/
    utils/
    store/                  # (minimal – see §4 State Strategy)
```

### 1.2 Folder Conventions

| Folder | Purpose |
|---|---|
| `src/pages/` | One file (or sub-folder) per route; route-level code-split via `React.lazy` |
| `src/components/` | Shared UI components (`ui/`, `layout/`, `domain/`) |
| `src/hooks/` | Custom React hooks — TanStack Query wrappers, auth hooks, etc. |
| `src/api/` | Typed fetcher + per-resource query/mutation functions |
| `src/types/` | TS types (auto-generated from OpenAPI + hand-written extras) |
| `src/mocks/` | MSW handlers, demo seed data, `browser.ts` setup |
| `src/utils/` | Pure helpers: formatters, validators, constants |
| `src/store/` | Thin context providers if truly needed (e.g. theme, demo-mode flag) |

### 1.3 TypeScript Type Generation

Types are auto-generated from `/contracts/openapi.yaml` using **openapi-typescript**:

```jsonc
// package.json scripts
"generate:types": "openapi-typescript ../contracts/openapi.yaml -o src/types/api.d.ts"
```

- Run on every contract update (CI step + pre-commit hook).
- Hand-written domain helpers live in `src/types/domain.ts` (e.g. `PromiseStatus` union, `AmountPaise` branded type).
- Never import from generated file directly in components; re-export clean aliases from `src/types/index.ts`.

### 1.4 MSW (Mock Service Worker)

- `src/mocks/browser.ts` — starts the MSW worker in `development` mode.
- `src/mocks/handlers/` — one handler file per resource group (auth, promises, merchants, dashboard, jobs).
- `src/mocks/seed/` — deterministic demo story data (consistent IDs, dates).
- MSW is **only activated** when `VITE_USE_MSW=true` (set by default in `.env.development`).
- When the real backend endpoint is ready, its handler is removed from `handlers/index.ts`.

## 2. Pages & Routes (React Router v6)

```tsx
// App.tsx — route tree (simplified)
<Routes>
  <Route path="/" element={<RootRedirect />} />
  <Route path="/login" element={<LoginPage />} />
  <Route path="/auth/callback" element={<AuthCallbackPage />} />

  {/* Protected routes — wrapped in <RequireAuth> */}
  <Route element={<RequireAuth />}>
    <Route path="/dashboard" element={<DashboardPage />} />
    <Route path="/promises" element={<PromisesPage />} />
    <Route path="/promises/:id" element={<PromiseDetailPage />} />
    <Route path="/merchants/:id" element={<MerchantPage />} />
    <Route path="/settings" element={<SettingsPage />} />
  </Route>

  {/* Dev / Demo only */}
  <Route path="/demo" element={<DemoPage />} />
</Routes>
```

| Route | Component File | Auth Required | Notes |
|---|---|---|---|
| `/` | `pages/Root.tsx` | — | Redirect: `/dashboard` if session cookie present, else `/login` |
| `/login` | `pages/Login.tsx` | No | Google OAuth button + Demo Mode button |
| `/auth/callback` | `pages/AuthCallback.tsx` | No | Exchanges code, sets session, redirects |
| `/dashboard` | `pages/Dashboard.tsx` | Yes | Summary cards, recent activity, sync status |
| `/promises` | `pages/Promises.tsx` | Yes | Paginated list, filters, CSV upload |
| `/promises/:id` | `pages/PromiseDetail.tsx` | Yes | Full promise view, escalation ladder, verification |
| `/merchants/:id` | `pages/Merchant.tsx` | Yes | Merchant stats, related promises |
| `/settings` | `pages/Settings.tsx` | Yes | Disconnect Gmail, delete account |
| `/demo` | `pages/Demo.tsx` | No | Demo simulator controls (dev/demo builds only) |

## 4. State Strategy

### 4.1 TanStack Query (Server State)

All server data lives in TanStack Query. No Redux, no Zustand.

```ts
// Query key conventions (src/api/queryKeys.ts)
export const queryKeys = {
  dashboard:    () => ['dashboard'] as const,
  promises:     (filters: PromiseFilters) => ['promises', filters] as const,
  promise:      (id: string) => ['promises', id] as const,
  merchant:     (id: string) => ['merchants', id] as const,
  job:          (id: string) => ['jobs', id] as const,
  syncStatus:   () => ['gmail', 'sync-status'] as const,
};
```

**Key patterns:**
- **`staleTime: 30_000`** for dashboard + list queries; `staleTime: 60_000` for merchant records.
- **Optimistic updates** on `PATCH /promises/:id` (status, user_note): update cache immediately, roll back on error.
- **Polling**: `refetchInterval: 3000` while a job is `pending` or `running`; stops when status is `done`/`failed`.
- **Invalidation**: after CSV upload job completes, invalidate `['promises']` and `['dashboard']`.

### 4.2 Forms (react-hook-form + zod)

Forms used:

|---|---|---|
| CSV Upload | `csvUploadSchema` | `POST /api/v1/credits/upload` (`CREDITS-01`) |

| Demo Simulate Credit | `simulateCreditSchema` | `POST /api/v1/demo/simulate` (`DEMO-01`) |

### 4.3 Session / Auth State

- Session is an **httpOnly cookie** set by the backend — the frontend never reads it directly.
- `useAuth` hook calls `GET /auth/me` (query key `['auth', 'me']`) to determine logged-in state.
- `RequireAuth` route wrapper suspends on the query; redirects if error/unauthorized.
- No auth tokens stored in `localStorage` or React state.

### 4.4 Minimal Context / Store (`src/store/`)

Only two thin contexts:

| Context | State |
|---|---|
| `ThemeContext` | `light`/`dark` toggle (persisted to `localStorage`) |
| `DemoModeContext` | Boolean flag read from `useAuth` data; suppresses real-sync UI |

## 6. API Integration Strategy

### 6.1 Typed Fetcher

```ts
// src/api/fetcher.ts
const BASE_URL = import.meta.env.VITE_API_BASE_URL;

export async function apiFetch<T>(
  path: string,
  options?: RequestInit,
): Promise<T> {
  const res = await fetch(`${BASE_URL}${path}`, {
    credentials: 'include',   // send session cookie
    headers: { 'Content-Type': 'application/json', ...options?.headers },
    ...options,
  });
  const envelope = await res.json();   // { data, error }
  if (!res.ok || envelope.error) throw new ApiError(envelope.error, res.status);
  return envelope.data as T;
}
```

`ApiError` carries `code` (e.g. `GMAIL_AUTH_EXPIRED`) and `message` for display.

### 6.2 Per-Resource Query Hooks (`src/hooks/`)

| Hook | Query Key | Endpoint ID |
|---|---|---|
| `useAuthMe()` | `['auth', 'me']` | `AUTH_ME` |
| `useDashboard()` | `['dashboard']` | `DASHBOARD_SUMMARY` |
| `usePromises(filters)` | `['promises', filters]` | `PROMISE_LIST` |
| `usePromise(id)` | `['promises', id]` | `PROMISE_GET` |
| `useMerchant(id)` | `['merchants', id]` | `MERCHANT_GET` |
| `useJob(id)` | `['jobs', id]` | `JOB_GET` |
| `useSyncStatus()` | `['gmail', 'sync-status']` | `GMAIL_SYNC_STATUS` |
| `useEscalationSteps(promiseId)` | `['promises', id, 'escalation']` | `ESCALATION_LIST` |

Mutation hooks: `usePatchPromise`, `useDismissPromise`, `useTriggerSync`, `useCsvUpload`, `useGenerateEscalation`.

### 6.3 MSW Handlers

```
src/mocks/handlers/
  auth.ts          # AUTH_ME, /auth/demo, /auth/google/start
  promises.ts      # PROMISE_LIST, PROMISE_GET, PROMISE_PATCH
  merchants.ts     # MERCHANT_GET
  dashboard.ts     # DASHBOARD_SUMMARY
  jobs.ts          # JOB_GET (simulates pending→done progression)
  gmail.ts         # GMAIL_SYNC, GMAIL_SYNC_STATUS
  bankCredits.ts   # CSV upload
  escalation.ts    # ESCALATION_LIST, ESCALATION_DRAFT
```

Handler pattern:
```ts
http.get('/api/v1/promises', ({ request }) => {
  const url = new URL(request.url);
  const status = url.searchParams.get('status');
  const data = seed.promises.filter(p => !status || p.status === status);
  return HttpResponse.json({ data: paginate(data), error: null });
});
```

### 6.4 Error Boundary Strategy

- `<PageErrorBoundary>` wraps each `<Route>` element; shows full-page error card.
- `<SectionErrorBoundary>` wraps individual heavy components (escalation, verification card).
- Toast notifications for mutation errors via `react-hot-toast` (or Sonner).
- Error code → user message mapping in `src/utils/errorMessages.ts`.

## 8. Validation & Edge Cases

### 8.1 Zod Schemas (must match Pydantic exactly)

```ts
// src/utils/schemas.ts
export const csvRowSchema = z.object({
  amount:    z.string().regex(/^\d+(\.\d{1,2})?$/, 'Invalid amount'),
  date:      z.string().regex(/^\d{4}-\d{2}-\d{2}$/, 'Use YYYY-MM-DD'),
  narration: z.string().min(1).max(500),
});

export const csvFileSchema = z.object({
  file: z
    .instanceof(File)
    .refine(f => f.type === 'text/csv' || f.name.endsWith('.csv'))
    .refine(f => f.size <= 5_000_000, 'Max 5 MB'),
});
```

Client-side CSV column validation happens before upload; on `CREDIT_UPLOAD_FAILED` from server, error is shown inline in the dropzone.

### 8.2 Edge Case Handling

| Edge Case | Handling |
|---|---|
| **Gmail token expired** | `useAuthMe` returns `gmail_connected: false`; `GmailConnectionCard` shows reconnect banner; sync button disabled |
| **LLM_UNAVAILABLE** | Mutation error → toast with retry button; promise stays `needs_review` |
| **SYNC_IN_PROGRESS** | `SyncStatusBanner` appears; sync button disabled; `useJob` polls every 3 s |
| **Partial refund (ambiguous match)** | `is_ambiguous: true` on `verification_matches`; `VerificationCard` shows amber warning "Multiple credits match — please confirm manually" |
| **Duplicate email** | Server returns `409 DUPLICATE_EMAIL`; toast "Already processed"; no duplicate row created |
| **Prompt injection flag** | `PromptInjectionFlag` chip renders on `PromiseMetaCard`; tooltip explains risk |
| **CSV wrong columns** | Inline error below dropzone lists missing columns; upload aborted |
| **Demo mode** | `DemoModeContext` suppresses Gmail sync UI; shows "Demo — no real emails" banner |
| **Cursor pagination** | `usePromises` accepts `cursor` param; "Load more" button appends next page via `fetchNextPage` (TanStack Query infinite query) |
| **Amount is null** | `AmountDisplay` shows "—"; due date null shows "No deadline set" |
